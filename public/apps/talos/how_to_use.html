How to use, change and extend this study

The study is a self-contained web application: open index.html from the Drive folder in any modern browser — no server, no internet connection needed. Everything, including the maps, orbit propagation and geolocation maths, runs locally. This page explains the conventions, where the numbers live, and how an engineer changes them.

Conventions

  • Sources. Claims carry markers like [R3-2]: R1–R5 are the five research notes, the number is the source entry inside that note. Every page ends with its sources; the full list is in References. All web sources were checked on 21 October 2026.
  • Estimates. Anything marked est. or "(est.)" is an engineering estimate derived in the study, not a measured or published value. Vendor claims are called claims.
  • Baseline. "TALOS-1" is the study's baseline satellite (issue 0.3). Where a page quotes a baseline number it reads it from assets/data/baseline.js or components.js, so the component list, the budgets page, the explorer and the simulators agree by construction.
  • Bands. UHF, L, S, C and X always use the same five colours throughout the study, in diagrams, charts and chips: UHF L S C X.
  • Theme and print. The sidebar buttons switch light/dark and print the current page (navigation is hidden in print). The demo console is dark by design.

Reusing the engine in your own tools

assets/js/orbit.js is dependency-free and exposes ORB: circular-orbit propagation with J2 secular drift, ECI/ECEF/geodetic conversions, look angles, footprint geometry, Walker and cluster generators, pass prediction, revisit grids, eclipse fraction, Doppler, and the TDOA/FDOA Jacobians, covariance and error-ellipse maths used by the simulators, plus ORB.RF for free-space loss, noise, sensitivity, aperture gain and the Stein-form timing/frequency accuracy bounds. It is deliberately simple (no drag, no higher-order gravity, Earth-surface constraint for geolocation) so that it can be read and checked; for mission analysis of record use STK, GMAT or Orekit and compare. geo.js draws the maps from the bundled Natural Earth country polygons so the application needs no tiles or network.

The demo console generates its emitters, detections and passes deterministically at load time from a seeded random generator tied to real pass geometry; it is a user-interface prototype, not a data product. The software architecture page describes the real pipeline it stands in for.

Extending the study

  • New pages: copy an existing page, keep the script block order (data → engine → app.js last) and add the page to SITEMAP in app.js so it appears in the navigation.
  • New diagrams: inline SVG using the classes in app.css (.box, .wire.rf, .lbl …) keeps them theme-aware.
  • Charts: Charts.bar / line / stack / range in charts.js follow the study's data-viz rules (one axis, fixed colour order, legends, table fallback).
  • Research notes: the Markdown files in research/ are the evidence base; update them first, then the data files, then the pages.

Known limits of issue 0.3

  • Prices are indicative ranges from public sources and marked unverified where the research could not confirm them; the next step is RFIs to the shortlisted suppliers.
  • Component masses and powers are allocations, not vendor data, reconciled to the research ranges.
  • The orbit engine ignores drag and uses a min-elevation cone for the footprint; revisit figures are therefore slightly optimistic at low elevation.
  • Regulatory statements reference the laws and their status as of the research date; a legal opinion is a Phase A deliverable.
